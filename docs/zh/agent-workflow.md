# 自循环 Agent 工作流

给一个提示词，多模态大模型进入 `观察 → 决策 → 执行` 自循环，每轮输出一个 `{think, tools[]}`，执行器严格解析并逐条执行一批**全部与图像工作有关**的技能，由 **Go 原生渲染引擎**合成成片。有明确的完成信号（`finish`），也能反复查看自己的作品（`view`）后再改。

## 核心特性

- **每次大模型请求 = 1 步**：一轮输出一个短思考标记 `think` + 一批 `tools`，状态跨轮累积，Agent 可「打底 → 查看 → 调整 → 完成」反复迭代。
- **技能全是图像工作**：`canvas`、`gen`、`stock`、`qrcode`、`qrdecode`、`add/set/del/clear`、`layers`、`copy`、`undo`、`view`、`finish`。
- **链底工具**：`view` 与 `finish` 必须出现在 `tools` 最后一个、每轮最多一个。
- **完成信号**：只有收到 `finish` 才交付成片。
- **系统级强制 view**：模型一旦发出 `finish`，系统先拦截并强制渲染「本次要交付的成片」回灌下一轮，附自检提示逼其核对；满意可再次 `finish` 确认，有瑕疵先修正。有次数上限（`MaxForceReviews`）防死循环。
- **主动创意·场景化构图**：主提示词教 Agent 别平铺贴图，把参考图变成画面里的「物件内容」——斜放设备屏幕 / 相框 / 橱窗 / 画中画；`gen{ref}` 图生图、`img` 用 `persp`/`shear` 做透视贴合。
- **写死 Few-shot + 缓存省钱**：主提示词与学习数据是编译期常量，拼成恒定 system 前缀，命中上游 prompt cache；动态内容一律放 user 消息。按「我的模型」独立开关 `learning`。
- **中间产物可管理**：`copy{src,as}` 物理复制产物存档/分叉；`undo{n}` 动作级回滚最近 n 个编辑（只退排版、不退素材）。
- **上下文限制**：每个 LLM 可配 `max_tokens`（输出上限）与 `context_limit`（输入字符上限，按预算裁较早消息、保图片与尾部要求）。

## 步数模型与耗尽策略

- 每次大模型请求 **1 步**；每次生图额外消耗该图像模型配置的单次步数（默认 30）；编辑/查看/完成不单独计步。
- 总步数预算由「我的模型」`max_steps` 控制（默认 100），不必用完。
- 每个模型独立配置步数用完仍未完成时的行为：`fail` 生成失败（默认）/ `partial` 返回当前半成品。
- 落库区分 `steps_used`（实际消耗）与 `llm_calls`（大模型请求次数）。

## 容错与鲁棒性

- **有容错、无臆造**：LLM 调用节流 + 429 指数退避重试；单轮 JSON 解析失败 / 工具非法时把错误反馈给模型在同轮重输出（有上限，不前进步数）；执行阶段 `set/del` 索引越界跳过并告警。
- **解析容错 ≠ 操作兜底**：颜色写 RGB 数组、工具名当 key、参数包在 `params`、尾随逗号等字段写法差异由解析层归一化；但未知工具、未知图层、链底违规、引用越界、生图/渲染失败仍是硬错误。
- **提示词分轮铁律**：首轮只建画布、此后每轮 ≤2 个动作、文字合并到单图层，防止上游输出被截断。

## 上下文拼接顺序

主提示词 → 紧凑上下文（剩余步数 + 图像模型列表）→ 产物表 → 上一轮结果（仅生图/查看有输出图）→ 用户要求。只有图片生成与查看会输出结果，编辑轮只回「编辑成功」状态文本。

## 仪表盘与轨迹

- 调用概述列表分页（`page` / `size`），详情展示每步思考过程与调用操作。
- API 专属参数 `trace: true`：响应附带每一步短 ThinkFlag（仅 step + think，不暴露技能）；默认不附带。
